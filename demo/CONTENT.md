# 维护纪念册内容

日常只需要编辑 `public/content.json`。当前 11 款游戏、角色素材和风格已经配置好，可以直接替换日期、时长和回忆，不用修改组件。

## 游戏与时间

| 字段 | 格式与用途 |
| --- | --- |
| `id` | 唯一且稳定的游戏标识，如 `peak`，不要随标题修改 |
| `title` | 展示的游戏名 |
| `playPeriod` | 周期对象 `{ "start": "2026-08-24", "end": "2026-08-30" }`；未知填 `null`。两个日期均为 `YYYY-MM-DD` |
| `hours` | 已提供记录覆盖期间的累计小时数，数字，例如 `3.5`；未知填 `null`，页面隐藏时长；`0` 则显示 0 h |
| `character` | 左侧透明角色 PNG 路径，现有游戏保持原值即可 |
| `memories` | 回忆数组，可增减、调整顺序，也可以为空 `[]` |

游戏按 `playPeriod.start` 从早到晚排序，同起点保持 JSON 数组顺序；未知周期稳定排在最后。每次进入默认选择排序后的第一款。左侧目录和全部游戏目录展示 `8.31–10.18`，右侧标题展示 `2026.8.31–10.18`；跨年时两端都显示年份。未知周期显示「时间待补充」。周期包含中间没有游玩的空档，不代表每天游玩。时长按去重后的周记录累加，不从起止日期或视频长度推算，也不代表 Steam 终身总时长。

回忆的 `date` 是那次回忆发生的具体日期，不影响游戏目录排序；省略时不显示，也不自动采用周报起点。除按用户要求保留的 Nomad Drive 外，原模拟回忆日期已清空，待真实记录补充。右侧统一先展示照片和文字，再展示视频；各类型内部保留 `memories` 原顺序。桌面为照片在左、文字在右且纸张顶部对齐，手机依次展示照片、文字、视频。

## 可复制的最小示例

以下完整 JSON 使用仓库已有素材，可以直接预览。它只包含一款游戏；实际编辑时保留现有其余游戏即可。

      "memories": [

          "id": "peak-video",
          "type": "video",
          "title": "差一点就上去了",
          "date": "2026-08-25",
          "src": "",
          "poster": "assets/peak-memory.png",
          "description": "这次差一点就能接住你。",
          "previewSeconds": 28
        },
        {
          "id": "peak-photo",
          "type": "gallery",
          "title": "山顶合影",
          "images": [
            { "src": "assets/peak-memory.png", "caption": "终于站稳了" }
          ]

        }
      ]

## 回忆类型

每条回忆都要有 `id`、`type`；图片组 `gallery` 的 `title` 可省略或填空字符串，其他类型仍需 `title`。`id` 在同一个游戏内不能重复，仅使用字母、数字、短横线、下划线；复制回忆时记得改 `id`。

| `type` | 内容字段 | 展示与交互 |
| --- | --- | --- |
| `video` | `src` 与 `poster` 至少填写一项；可选 `description`、`previewSeconds` | 原生视频播放器；有视频无封面时由浏览器显示视频画面，没有视频地址时显示动态封面占位 |
| `featuredVideo` | 与 `video` 相同 | 宽幅特别剪辑卡片；双影奇境已有 `split-special` 槽位 |
| `gallery` | 必填非空 `images` 数组，每张只需 `src`；组标题 `title`、图片说明 `caption` 均可省略 | 无文字时不留标题或说明空位；一张图也支持，多张可通过居中按钮、图片区域滚轮、触屏滑动翻页，也可点击放大 |
| `text` | 必填 `excerpt`；可选 `paragraphs` 字符串数组 | 摘要常驻；有补充段落才显示展开按钮 |

`previewSeconds` 只控制 mock 封面动画，不决定真实视频时长。真实视频由播放器读取媒体信息。图片和视频描述按普通文本展示，换段使用 `paragraphs`；不解析 HTML 或 Markdown。

不需要图片标题或说明时，最简配置为：

```json
{
  "id": "screenshots",
  "type": "gallery",
  "images": [{ "src": "assets/games/peak/001.jpg" }]
}
```

没有封面时，`poster` 可省略或填空字符串，只填视频 `src` 即可（`featuredVideo` 同样支持）。有封面保持 `preload="none"`；无封面使用原生 `preload="metadata"`，加载到首帧后由浏览器显示，不自动播放、不额外截帧或跳转播放时间。预加载只是浏览器提示，实际流量和未播放前能否显示画面取决于浏览器与文件编码；首帧本身是黑场时也会显示黑色。无视频地址的预留回忆仍需 `poster`。

已将用户清单的 72 个视频接入 `https://uu-memories-1.oss-cn-hongkong.aliyuncs.com/uu-video/games/{游戏ID}/{文件名}.mp4`。本地 `bsl` 对应 OSS `chameleon`，`fish` 对应 `fishing`，其他目录同名；中文文件名在 URL 中进行百分号编码，标题保留原文件名去掉扩展名。描述仅根据名称撰写，后续可直接修改 `public/content.json` 中各视频的 `title`、`description`、`src`。不根据文件顺序补造日期，不给真实视频沿用演示封面或演示时长。

## 可选的小交互

- 每款游戏先展示前 3 段视频，更多视频通过「还有 N 个呢」展开；收起时卸载后续播放器，暂停播放并停止其预加载。展开状态在本次纪念册内保留，刷新或重播开屏后重置。播放一段真实视频会自动暂停其他视频，保留它们的播放位置。
- `gallery.images` 中每张照片可加 `"note": "想写在背面的话。"`。照片放大后，点击照片本身翻到背面留言，再点翻回；支持 Enter / 空格操作，不另加切换按钮。切换照片自动回到正面。省略或留空时照片不可翻面，原 `caption` 仍是照片说明，两者相互独立。当前每款游戏首图有一句可修改的留言草稿。
- 顶层 `avatarMessages` 是头像彩蛋的文字数组，例如 `["加密通话中。", "全部愣住了。"]`。每点一次头像都会摇动并喷出彩带，第 1–9 次逐渐增加，第 10 次达到最大效果、加入 🍊 和 🎂，此时才轮流显示一条文案，气泡 4 秒后消失。随后开始下一轮 10 次点击；切换游戏不打断计数，刷新或重播开屏重置。省略此字段或填 `[]` 即关闭彩蛋。减少动态效果模式不摇动或飞散，仅保留第 10 次的静态 emoji 和文字。
- 已浏览游戏在左侧目录和全部游戏目录显示一个淡金色小点；仅标记实际进入的游戏，不标记滚轮经过的预选项。记录只保留在本次纪念册内，刷新或重播后清空，不写入本地存储。

游戏可保留这些可选字段：`englishTitle`（参与搜索）、`platform`（默认 Steam）、`paper`（默认 `#ede9f3`）、`ink`（默认 `#7e6c96`）、`layout`（默认 `auto`）。现有角色、配色无需随内容更新重新填写。

所有游戏统一使用图文在前、视频在后的排版。桌面将照片与文字分栏、顶部对齐，手机依次纵向排列；只有照片或只有文字时，该区域占满可用宽度。旧的 `layout` 字段继续接受，以兼容已有 JSON，但不再启用会把图文排到视频后面的错位预设。

## 路径、更新与校验

- 本地图片放 `public/assets/`，例如文件 `public/assets/photos/peak.jpg` 在 JSON 中写 `assets/photos/peak.jpg`。不要填写电脑绝对路径；不要以 `/assets/` 开头，这会绕过 GitHub Pages 的仓库子目录。
- 外部图片或视频在 `src` 填完整 HTTPS 直链。视频应为能直接播放的媒体文件地址，而不是网盘分享页或视频网站页面；可优先准备兼容浏览器的 MP4 文件。
- 当前 60 张图片的生产地址由 `oss-images.json` 统一映射至 OSS 官方 HTTPS 域名，包含 30 张真实截图；JSON 中原路径无需改写。更新图片需上传新的带哈希对象并更新映射，不能只覆盖本地原图。开发模式仍使用本地图片，生产预览需在允许的 `https://7uuuuuuu.cn` 来源下验证，localhost 不在现有防盗链及 CORS 白名单中。
- JSON 不能包含注释或尾随逗号。时长写数字 `12.5`，不要写 `"12.5小时"`。日期不要写 `2026/7/12`。
- `demoMode` 当前按用户要求设为 `false`，隐藏页尾的周期、时长和演示说明；不影响排序与回忆内容，也不表示所有文字均已定稿。
- 在 `demo` 目录运行 `npm run check:content`，校验字段、重复 ID、日期和本地素材。运行 `npm run build` 和 `npm test` 验证后提交推送，现有 GitHub Pages 工作流会重新部署。远程链接播放情况需要实际访问验证，构建不会下载视频。

版本 4 将版本 3 的 `firstTime` 替换为 `playPeriod` 起止周期，旧版模拟首次日期不再保留。回忆的 `date` 保持原名，但省略时不再继承游戏日期。仓库数据、校验和界面已整体迁移。
